# Cover letter (optional, on request)

Not built by default. Offered at Step 6 (one question before the Word resume is built), or any time the user says `Build my cover letter for [Role/Company].`

## Steps

1. Use `references/templates/cover-letter-template.md` for the structure. Match the voice in file 01.
2. **Company research.** GapToGrowth makes no network requests by default, so ask first, in one message:
   "To make the letter specific, I need a little about [Company]. You can paste the 'About' or mission text from their website, or let me look it up on the web. Reply with one of: `I'll paste it` · `Look it up` · `Skip research`"
   - `I'll paste it`: use only what they paste.
   - `Look it up`: search the official site first, then press coverage. Confirm the company's correct brand name (do not assume the name in the JD header is right). Use only what you actually find.
   - `Skip research`: write the letter from the JD alone and do not state anything about the company's mission.
   Never invent company facts, products, values, or news.
3. Open with a genuine connection between the company's mission (when known) and the user's real work. Avoid a generic "I'm excited about this role" opener.
4. Use 3 to 5 JD themes, taken from this JD's AUTO-ADDED and Category A keywords. Give each one real example from verified experience (files 02 and 03). Same honesty rule as the resume.
5. Add one short "why I'm a strong fit / why this company" paragraph only when the role is competitive or the user does not check every box. When the user says they want to apply with confidence despite a gap, name the gap briefly and honestly, then pivot to why they will deliver. Do not hedge at length.
6. Write in the user's own professional phrasing, synthesized from the facts. Never lightly reword what they typed in chat.
7. Before writing any certification or status-bearing fact, check it against file 03 (see the verify-before-writing rule).
8. No em dashes. Save as `Cover Letters/{FileName}_RoleName_CompanyName_CoverLetter.docx` (create the folder if missing, never overwrite). Ask the user to review the Word draft before treating it as final.
9. Record in this JD's decisions file that a cover letter was built, and its file name.
